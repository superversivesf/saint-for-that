# Saint For That — Design Spec

Date: 2026-08-16
Status: Approved

## Overview

A searchable website of Catholic saints: who they are, what they intercede
for, and their life story. Inspired by "There Is a Saint for That" by
Peter's Barque. Users can search by need ("lost keys", "anxiety") or by
saint name, and browse by category. Built as a static site with a data
schema designed to be consumed later by a standalone Flutter app.

## Goals

- Search by need → saints who intercede for it
- Search by saint name → profile with bio, patronages, prayer
- Browse by category (jobs, illness, travel, everyday, ...)
- Rich profiles: multi-paragraph bio, feast day, canonization date,
  patronages, optional prayer, public-domain image, sources
- Deeply mobile-friendly responsive layout
- Static output, hostable anywhere (GitHub Pages, Cloudflare Pages, VPS)
- Shared data schema so a future Flutter app consumes the same JSON

## Non-Goals (v1)

- User accounts, comments, or any backend
- Flutter app itself (schema-compatible only)
- Self-hosted images (public-domain URLs only)
- Hosted search service (Algolia etc.)

## Data Model

One JSON file per saint at `data/saints/<slug>.json`:

```json
{
  "slug": "anthony-of-padua",
  "name": "St. Anthony of Padua",
  "feastDay": "06-13",
  "canonized": "1232",
  "bio": "2-3 paragraphs...",
  "patronages": [
    { "need": "lost items", "category": "everyday" },
    { "need": "travelers", "category": "travel" }
  ],
  "prayer": "optional short prayer",
  "image": {
    "url": "https://commons.wikimedia.org/...",
    "attribution": "..."
  },
  "sources": ["https://..."]
}
```

Rules:

- `patronages[].need` is the searchable intercession text — the core of
  the product
- `patronages[].category` enables browse-by-category
- Schema validated at build time with zod; invalid data fails the build
- Unique slugs enforced by validation
- Flutter app later reads the same files — no schema drift

## Site Architecture

All pages static, generated by Astro:

| Route | Content |
|---|---|
| `/` | Hero with search box ("What do you need a saint for?"), category chips, featured saints |
| `/search` | Full search UI (Pagefind), results as cards |
| `/saints/` | Alphabetical index, grouped by letter |
| `/saints/<slug>/` | Rich profile: image, bio, feast day, patronages, prayer, sources |
| `/categories/<category>/` | Browse by need category |
| `/about` | Project story, song inspiration (with link to "There Is a Saint for That" by Peter's Barque), data sources |

Search:

- Pagefind index built at build time from generated HTML
- Instant, fuzzy, works offline after load
- Matches saint names AND patronages ("lost keys" → Anthony)
- No server, no API — pure static output

Mobile-first:

- Tailwind responsive layout
- Large tap targets
- Sticky search bar
- Cards stack to single column on small screens

Footer (site-wide):

- Link to the song "There Is a Saint for That" by Peter's Barque
- Link to /about

## Content Pipeline & Tooling

- 200 saints as JSON files; curation is the bulk of the work
- Build-time zod validation: required fields, valid dates, unique slugs
- `scripts/import.ts`: seed from CSV/JSON dump for future external
  imports
- Images: public-domain Wikimedia URLs, attribution rendered on profile
  pages
- Astro content collections for type-safe template access

Stack: Node 20+, pnpm, Astro 5, Tailwind 4, Pagefind, zod.
Tests: vitest for schema validation + build smoke test (every saint
renders, every page returns 200).

## Error Handling

- Invalid saint data → build fails with file path and field name
- Missing image URL → profile renders without image (graceful)
- Search with no results → friendly empty state suggesting categories
- Broken external image → `onerror` fallback placeholder

## Testing

- Unit: zod schema accepts valid fixtures, rejects each invalid case
- Build smoke: all 200 saint pages + index + categories render, HTTP 200
- Search: Pagefind index contains saint names and patronages
